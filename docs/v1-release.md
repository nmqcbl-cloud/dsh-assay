# dsh-agent-eval v1.0 交付说明（2026-09-28）

## 一、项目定位

**一句话**：`dsh-agent-eval` 是一个 dsh 工具插件，注册工具 `eval_run_dual`，
跑「双后端对比评测」，回答**迁移接受门**的问题 —— 候选模型能不能替代基线模型。

它的产出是**给迁移决策用的证据**，不是 benchmark 排名。

**它不回答**「哪个模型更好」，只回答「**能不能换**」。成本门顺带说一句「值不值得换」。

## 三、三个门的最终结果

| 门 | 性质 | v1.0 结果 |
|---|---|---|
| **① 质量门** | 一票否决 | ✅ **54/54 产物判据通过**（三批次）。本次交付跑 4 个可解套件 × 2 后端 = 8/8 通过，另对累积的 **90/90 份快照**独立复核一致 |
| **② 兼容性门** | 一票否决 | ⚠️ `system 字段格式` **pass**、`cache_control 使用` **not_checked** |
| **③ 成本门** | 建议性（**从不否决**） | ✅ flash 低 **53–78%**（跨批 n=9，三批次 15/15 判定一致） |
| ~~步数门~~ | **已删除** | 只作诊断字段输出，不设阈值、不出判定 |

判定顺序（`src/verdict.ts`，纯函数、零 token）：

```
① 质量门有失败项？          → 不可迁移
② 兼容性门有 fail 项？      → 不可迁移（与质量门/成本门结果无关）
③ 兼容性门有 not_checked？  → 有条件迁移
④ 其余（两门全过）          → 可迁移
```

**成本门不参与否决** —— 一个把任务做错的模型可能非常便宜，一个贵 3 倍的模型也可能
完全正确。把成本写进否决是范畴错误。

### 3.1 一个值得记录的观察：区间在动，判定不动

本次单跑的绝对成本，**10 个侧值里有 5 个落在 n=9 历史区间之外**：

| 套件 | 侧 | 本次 | 历史区间（n=9） |
|---|---|---|---|
| 01 | pro | 0.000336 | [0.000368, 0.001342] ↓ 略低于下界 |
| 01 | flash | 0.000111 | [0.000080, 0.000100] ↑ 略高于上界 |
| 02 | pro | 0.001543 | [0.001600, 0.002118] ↓ 略低于下界 |
| 03 | pro | 0.003371 | [0.002768, 0.003219] ↑ 略高于上界 |
| 03 | flash | 0.000731 | [0.000764, 0.001100] ↓ 略低于下界 |

**所以历史区间是「观测范围」，不是「预测区间」。** 但同一趟里两列的相对关系没变：
本次节省 62.0%–78.3%，与历史的 53.2%–78.1% 同处一个量级，
**5/5 套件的「flash 显著更便宜」判定都成立。**

这正是设计所主张的：**成本门采信的是相对关系，不是点值**；
而区间给出的是量级，不是边界。

## 四、已知限制 —— **这些是设计边界，不是未完成的 TODO**

> 这一节是这个项目最诚实也最重要的部分。下列每一项都**不是**「差几个功能就完美」，
> 而是**这个工具在当前设计下原理上做不到、或刻意不做**的事。
> 读的人应当据此判断「v1.0 的结论在什么条件下成立」，而不是猜「还有什么没做完」。

### 1. `cache_control` 的效力**静态不可判定** —— 这是原理边界，不是实现缺口

`cache_control` 由 harness 在 `anthropic-messages` 协议下**运行时生成、每次请求必发**，
不存在于任何配置文件里。所以「扫配置看它有没有被用上」这种检查**恒返回"没扫到"**，
而它实际上每次都在发 —— 那会是一个**假通过**，比不检查更糟。

端点收到后**是否真的据此建立前缀缓存**，只有发一次请求看计费才能验。
当前实现因此诚实地报 `not_checked`，并把「还差一次探针请求」写进风险清单。

**后果**：判定恒为「有条件迁移」。**这是 v1.0 的预期状态，不是 bug。**

**旁证（≠判定）**：按成本反解落在 miss 档的 token 数，命中率实测在 **0%–99% 间波动**：

| 观测 | 命中率 |
|---|---|
| v3 三批次 30 次内层运行 | 94.2% – 98.8% |
| 相隔数小时的孤立运行 | pro 0.0%（成本恰好等于全价理论值）、flash 30.2% |

前缀缓存有 TTL，**冷启动必然全价**。加上 DeepSeek 本身有自动前缀缓存、
分不清是谁起的作用 —— 所以证据只能写进报告供人看，不能变成 `pass`。

### 2. 步数**没有测量能力** —— 已从判据中删除，只作诊断

同一配置、相隔 20 分钟的三批次，03 给出**三个不同的判定**（v1 pro 多 / v2 flash 多 /
v3 不显著），05 给出两个。而它要测的差距本身只有 1–2 步 —— **信噪比 ≈ 1**。

**批次效应查不出根因也控制不了**（模型服务侧对用户不透明：路由到哪个推理集群、
KV cache 状态、温度是否非零）。设计上不查，只规避：**只做轮内对比，不做跨轮对比。**

步数只保留两个诊断用途：发现异常漂移（如候选步数突然翻倍 → 疑似重试循环）、
给成本变化做归因。**绝不设阈值。**

### 3. 绝对成本**跨轮不可比**（相对关系可比）

本次交付的观察（第 3.1 节）已经证实：单次跑的绝对成本会落在历史区间之外。
跨轮可比的是**同一趟内两列的相对关系** —— 同批跑，批次效应与缓存状态同向作用于两列。

### 4. 套件池**不覆盖编码场景的完整谱系**

当前 5 个套件是「单步问答 / 单文件修复 / 多文件定位 / CLI 解析落盘 / 失败报告」。

**没有覆盖**：长上下文（>100k）、多轮对话、大范围重构、并发工具调用、真实仓库规模的任务。

→ **接受门的适用范围必须声明为「当前套件池覆盖的任务类型」**，
**不能读成「这两个模型在任何任务上等价」。**

### 5. 只有 **1 对模型**的数据

`deepseek-v4-pro` vs `deepseek-flash`。「成本差异稳定、步数差异不可复现」这个模式
**是否普遍，未知** —— 需要再跑一对（如 v4-pro vs Claude）才知道。
`src/pricing.ts` 里已经有 Claude 的价目，但**没有 Claude 的凭证，那一列从未跑过**。

### 6. `01-single-step` **不参与任何判定**

它是环境探针。没有工作区、没有产物，唯一内容判据 `output_contains: "Harness"`
查的是**措辞**，而措辞正是本设计论证过不该进断言的东西。
它在多批次运行里都通过，但**那是环境可用的读数，不能读成质量证据**。

### 7. 无跨模型的价值判断

本门只回答「**能不能**换」，不回答「**该不该**换」。

## 六、复现指引

### 6.1 离线回归（零成本，不联网）

```bash
cd /Users/mac/dsh-agent-eval
npm run test:offline     # 14 组 121 项断言，全绿
```

这是改动后**必跑**的回归手段，不需要 key。

### 6.2 跑一次完整交付（5 套件 × 1 次，约 ¥0.12）

```bash
mkdir -p /tmp/v1-release
eval "$(grep -E '^export ANTHROPIC_AUTH_TOKEN=' "$HOME/.zshrc")"
export DEEPSEEK_API_KEY="$ANTHROPIC_AUTH_TOKEN"
unset ANTHROPIC_AUTH_TOKEN

for suite in 01-single-step 02-two-step 03-multi-file 04-tool-chain 05-failure-report; do
  dsh --profile eval-runner headless --json \
    "只调用 eval_run_dual，suite 填 multi-step/${suite}，拿到结果后原样输出，不要做任何其他操作" \
    > /tmp/v1-release/$suite.ndjson 2>&1
done
```

**环境接线要点**（踩过的坑）：

- key 在 `~/.zshrc` 的 `ANTHROPIC_AUTH_TOKEN`，但 **`source ~/.zshrc` 取不到**
  （非交互 shell 提前 return）—— 必须只 `eval` 那一行，如上。
- **`ANTHROPIC_*` 环境变量对 dsh 是惰性的**（实测无效），所以要把值**改名**成
  `DEEPSEEK_API_KEY`。换路由只能走 `--patch`，插件已在内部生成。
- 变量后面**不要紧跟全角标点**（`${suite}，` 而不是 `$suite，`）——
  zsh 会把多字节字符吃进变量名，`set -u` 下直接报 unbound variable。

### 6.3 独立复核产物（零成本）

产物断言是插件自己算的，**用另一个脚本独立复核快照**是防止"自己验自己"的手段：

```bash
node /tmp/verify-asserts.mjs
# 真实快照：90 通过 / 0 失败
# 原始模板：4 被拒 / 0 误通过
```
