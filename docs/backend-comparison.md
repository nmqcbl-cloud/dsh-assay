# 双后端对比：deepseek-v4-pro vs deepseek-flash（2026-09-28）

第一份真正的双后端对比数据。此前所有多步数据都是 v4-pro 自对比（用来验证套件本身、
建立散度基线），这一轮才第一次让两列跑**不同的模型**。

- 5 个套件 × 3 次 = **15 组对比 / 30 次内层运行**
- `baseline` = `deepseek-v4-pro`，`candidate` = `deepseek-flash`
- 外层用严格指令（「只调用 eval_run_dual，拿到结果后原样输出，不要做任何其他操作」）
- 本轮内层总花费 **$0.0505 ≈ ¥0.36**
- 原始 NDJSON 在 `/tmp/backend-compare/`，未入库

**外层噪音已清零**：15 组的外层 agent 全部只调用了 1 次 `eval_run_dual`，无一例外。
严格指令 + 按 `callId` 提取这两条措施都生效了。

## 一、每套件数据

「显著」的判据是**两列 3 次观测的取值区间是否重叠**：不重叠记显著，重叠记在随机性范围内。
（n=3 的检验力有限：区间**不重叠**是较强证据；区间**重叠**只是弱证据，不足以断言"无差异"。）

### 01-single-step —— 单步基线

| 指标 | v4-pro 中位数 | flash 中位数 | 差异 | 判定 | pro 自散度 |
|---|---|---|---|---|---|
| 步数 | 1 | 1 | 0 | 重叠 → 不显著 | 0 |
| 输入 Token | 5569 | 5505 | −64 | 不重叠 → 显著 | 0 |
| 输出 Token | 121 | 126 | +5 | 重叠 → 不显著 | 69 |
| 成本 USD | 0.0004 | 0.0001 | −0.0003 | 不重叠 → 显著 | 0.0001 |

原始值 —— pro 步数 `1,1,1` / flash `1,1,1`；pro 输入 `5569,5569,5569` / flash `5505,5505,5505`。

两列步数完全相同，符合预期（这个任务不需要工具）。**输入 token 差 64 是固定的**，三次都差 64
（自散度 0），是 system prompt / 模板的固定差异，不是行为差异。成本那一行的"显著"要打折看：
报告渲染只到小数点后 4 位，flash 的真实成本约 0.00007，被量化成 0.0001，精度不够支撑结论。

## 三、05 步数复测：更正一个判断

**判断一（「`{10,6,6,6}` 里的 10 可能是外层噪音」）不成立。** 两条独立证据：

1. **机制上不可能**：`avgSteps = 内层 step_end 总数 / 套件步数`（`src/eval-runner.ts:373`），
   而内层 `step_end` 来自 `runOneBackend` 自己 spawn 的子进程 stdout。外层 agent 的往返
   发生在外层会话里，**根本不经过内层计数器**。外层的 4 次翻文件既不会加也不会减内层步数。
2. **实测干净**：观测轮 05 那次的 NDJSON 里，外层只调用了 **1 次** `eval_run_dual`、
   外层 `step_end` 只有 **2 条**（一次调工具 + 一次作答），零翻文件。它仍然报 10 步。

本轮用严格指令复测，**pro 三次是 `{10, 6, 8}`**——`10` 又出现了一次。

**合并所有干净样本（n=7）**：

| 来源 | pro baseline 步数 |
|---|---|
| 05 波动测试（严格指令） | 6, 6, 6 |
| 观测轮（外层仅 1 次工具调用） | 10 |
| 本轮（严格指令） | 10, 6, 8 |
| **合并** | **6, 6, 6, 6, 8, 10, 10** |

中位数 **6**，区间 **6–10**，极差 **4**。

→ **你预设的升级条件（"如果是 `{10,6,6}` 就升级为 5 次取中位数"）已触发。**
而且不止：n=3 时看到的极差 0 或 2 是样本量制造的假象，n=7 才暴露出极差 4。

flash 三次是 `{8,9,7}`（中位数 8，极差 2），也在这个范围内。

**05 的步数：不可用单次值，也不可用 3 次中位数定阈值。**

## 五、对接受门采样策略的最终建议

1. **每个套件跑 ≥5 次取中位数**（不是 3 次）。05 的 7 样本给出极差 4，3 样本给出 0–2——
   3 次会系统性地低估散度。样本量不足时，"散度稳定"是个假象。
2. **断言写在产物上，不写在步数或措辞上。** 本轮 24/24 产物判据全部稳定；
   而步数在 05 上极差 4、在 03 上换模型整体平移 2。
3. **成本用区间不用点值，但要报**。成本是本轮对模型替换最敏感的指标（全部显著、稳定低 70–80%），
   作为**容量规划**输入很有用；作为**质量判据**没用（它不携带正确性信息）。
4. **步数阈值必须按模型分别标定，不能跨模型复用**。03 上 pro 稳定 7、flash 稳定 5，
   写死"≤7"会让 flash 永远通过、pro 永远贴线。
5. **报告渲染的小数位要够**。`成本(USD)` 目前 `.toFixed(4)`，flash 在 01 上真实成本约
   `0.00007` 被量化成 `0.0001`（误差 ~40%）。**建议渲染改成 6 位**——这是渲染层的事，
   不动 `SuiteResult` 接口。改之前本轮的 01 成本列只能定性看。
6. **不可解任务不是"差异放大器"。** 本轮唯一的显著步数差异出在可解任务（03）上；
   05 上两列完全重叠。选套件时不要预设"越不可解越能区分模型"。

## 七、局限

1. **n=3 的显著性检验力有限**。本表用"区间是否重叠"是为了不引入统计假设，但区间重叠
   不等于无差异。清单里的"显著"较可信，"不显著"只能读成"这三次没看出差异"。
2. **05 的 pro 列散度压倒一切**，中位数差异在这列上基本没有信息量。
3. **成本列受 4 位小数渲染限制**，01/02 的小额成本有量化误差（见第五节第 5 条）。
4. **外层 agent 的开销没计入**。它走 flash、只调一次工具，量级远小于内层，但没有精确数字。
5. **本轮只跑了 5 个套件、1 对模型**。结论不外推到其他模型对（如 v4-pro vs Claude）——
   「成本差异显著、步数差异罕见」这个模式是否普遍，需要再跑一对才知道。
